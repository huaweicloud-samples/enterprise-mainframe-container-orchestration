# 架构说明（Architecture）

## 1. 目标

为大型机（mainframe）应用现代化后的 Java 负载提供一套**容器化编排环境**：在私有网络内通过托管容器平台同时承载**批处理任务**（一次性运行）与**实时服务**（常驻副本 + 内部负载均衡），并配齐对象存储、关系数据库、密钥管理、镜像仓库、监控告警等周边能力。

## 2. 总体架构

```
                         │  │              │   │   TCP :3090        │  │
                         │  │  Job(批处理)  │───│        │           │  │
                         │  │  Deployment  │   │        ▼           │  │
                         │  │ (实时服务)    │   │  Deployment 副本    │  │
                         │  └──────┬───────┘   └────────────────────┘  │
                         │         │                                    │
                         │  ┌──────▼───────┐  ┌─────────────────────┐  │
                         │  │  RDS(PostgreSQL 主备) │  OBS 输入/输出桶   │  │
                         │  └──────────────┘  └─────────────────────┘  │
                         │  ┌──────────────┐  ┌─────────────────────┐  │

```

## 3. 模块职责

| 模块 | 职责 | 关键资源 |
|---|---|---|
| `network` | 私有网络底座：VPC、私有/公有子网、可选 NAT、数据库与业务安全组 | `huaweicloud_vpc` / `huaweicloud_vpc_subnet` / `huaweicloud_nat_gateway` / `huaweicloud_networking_secgroup` |
| `storage` | 批处理输入/输出桶（版本化、加密、生命周期） | `huaweicloud_obs_bucket` |
| `kms` | 数据加密主密钥 | `huaweicloud_kms_key` |
| `database` | PostgreSQL 主备 + 参数组 + 双凭据 + 定时备份 | `huaweicloud_rds_instance` / `huaweicloud_csms_secret` / `huaweicloud_cbr_vault` |
| `iam` | 容器平台访问对象存储的委托 | `huaweicloud_iam_agency` |
| `batch` | 批处理任务（一次性 Job）+ 结果通知 | `kubernetes_job_v1` |
| `realtime_service` | 实时服务：内部负载均衡 + 常驻 Deployment | `huaweicloud_elb_loadbalancer` / `kubernetes_deployment_v1` / `kubernetes_service_v1` |
| `monitoring` | 数据库 / 负载均衡 / 集群指标告警 → SMN | `huaweicloud_ces_alarmrule` |

## 4. 数据与访问路径

### 4.1 批处理链路

1. 触发一次性 Job（CCE 拉取 SWR 业务镜像）；
2. Job 从输入桶读取待处理数据，处理后写入输出桶；
3. Job 连接 PostgreSQL 读写业务数据（密码来自 CSMS 凭据，地址来自部署输出）；
4. 完成后向 SMN 主题发送结果通知（订阅者自行配置邮件/短信等）。

### 4.2 实时服务链路

1. VPC 内客户端访问内部负载均衡 ELB（TCP 3090）；
2. CCE 云控制器在 ELB 上创建监听器与后端，将流量转发到 Deployment 副本（Pod IP）；
3. 副本从数据库读取业务数据并响应。

### 4.3 安全与私网

- 数据库安全组仅放行同 VPC 网段（5432）；
- 实时服务安全组仅放行 VPC 网段与可配置的附加 CIDR（3090）；
- 业务工作负载默认不绑定公网 IP；批处理需出公网时通过 NAT 网关 + SNAT。

## 5. 高可用设计

| 层 | 设计 |
|---|---|
| 数据库 | RDS PostgreSQL **主备**（async 复制），同 VPC 多可用区 |
| 实时服务 | Deployment **副本数 2**，ELB 健康检查自动剔除异常后端 |
| 容器平台 | CCE 集群 + 节点池（多节点），节点故障由集群调度恢复 |
| 密钥与备份 | KMS 主密钥轮换 + CBR 每日备份（保留 14 份） |

## 6. 关键设计决策说明

- **批处理用 Kubernetes Job 而非常驻服务**：大型机现代化后的批处理模块（月度结算、日终跑批等）语义为「执行一次、结束即退出」，Job 天然符合，资源用完自动释放。
- **实时服务用内部负载均衡而非公网入口**：联机交易接口只在内网可达，避免直接暴露公网，符合典型大型机应用安全边界。
- **数据库用 RDS 托管而非自建**：保留主备高可用、自动备份、参数组管理能力，减少运维负担。
- **监控走指标告警**：数据库 CPU/内存/连接/存储/复制延迟、负载均衡健康主机数、集群节点状态均可告警，统一经 SMN 触达订阅者。
